# Проверка поиска и ссылок — 28.09.2026

Изменения применены к `trip-source-updated`. Сайт запущен на http://127.0.0.1:3000/.

## Что работает

- Общие редактируемые даты отправления/заезда и возвращения/выезда; отдельные сроки групп семьи.
- Состав пассажиров сохраняется в модели выбранного варианта. Изменение формы поиска не подменяет состав старой карточки.
- Aviasales: маршрут IATA, обе даты, взрослые, дети и младенцы; прямая выдача и запасная заполненная форма.
- Booking: направление, заезд/выезд, взрослые, число детей, каждый возраст, один номер в каждом запросе.
- Островок: даты и состав номера для сопоставленных курортов: Макади-Бей, Белек, Као-Лак, Рас-эль-Хайма, Анталья. Неизвестные курорты не получают выдуманный URL.
- Распределение гостей по номерам; проверка, что все взрослые и дети распределены ровно один раз. Можно добавить номер и выбрать его группу.
- Российский пакет / зарубежный пакет: отдельный запрос полного тура на каждый номер, даты без допуска, ночи, аэропорты, страна/курорт, возраста, питание, звёздность. Запрос можно скачать как JSON. Это внутренний формат, не обещание совместимости с API поставщика.
- Цена пакета требует фактического оператора, страны оператора, отеля, типа номера, питания, подтверждения включённых перелётов и проживания, условий продажи и оплаты.
- Для зарубежного тура — отдельная строка стоимости дороги до аэропорта старта и обратно, ночёвок и остальных доплат.
- Ввод цены, HTTPS-ссылки, описания и подтверждения; сумма только внесённых предложений, список незаполненных расходов.
- Старые цены исключаются при изменении параметров своей строки; сохранение в браузере привязано к составу семьи и числу номеров.
- Таблица фактических расходов и строки найденных цен в карточке и сравнении используют один расчёт по внешним источникам. Учебные цены снова видны в демо-карточках и отдельной строке сравнения с меткой SYNTHETIC; они не подставляются в фактическую сумму. Неизвестные расходы не заменяются нулями или модельными суммами.
- Минимум открытой выдачи Aviasales можно сохранить как DEEPLINK / LIMITED_REAL / PUBLIC_PAGE_OBSERVED / bookable:unknown. Он учитывается в промежуточной сумме за всех пассажиров без умножения, но требует проверки выбранного тарифа. URL проверяется на совпадение маршрута, дат и количества пассажиров.
- Полная стоимость и сортировка по полной цене появляются только при заполнении и подтверждении всех расходов. Частичные суммы не объявляются полной стоимостью или доказательством экономии.

## Проверки

`pnpm typecheck` — PASS.

`scripts/test_specific_search.cjs` — PASS: URL, невозможные и прошедшие даты, ближайший годовой цикл Aviasales, возрастные категории, split-family, occupancy, российские/зарубежные запросы тура, полные/частичные суммы, исключение устаревших и синтетических цен, обязательные данные пакета, positioning.

В браузере проверены: синхронное изменение дат во всех ссылках; распределение 2 взрослых + дети 5/7/9 по двум номерам; отказ применить цену без источника и подтверждения; формы российского и зарубежного пакета, раздельный positioning.

Дополнительно проверен маршрут SVO–HKT 29.09–07.10.2026, 2 взрослых + дети 5/7/9: наблюдаемая цена 263 999 RUB включена в строку перелёта, промежуточную сумму и B2B-карточку Као-Лака. Остальные 8 расходов не заполнены; тариф требует проверки. Повторное открытие и перезагрузка сохраняют сумму. Возвращение 08.10 исключает цену; восстановление 07.10 возвращает её. Синтетические 96 700 RUB и 112 442 RUB в основном расчёте не используются.

После замечания пользователя проверено, что localhost:3000 и localhost:8000 не слушали запросы. Оба сервера перезапущены и ответили HTTP 200. В демо-режиме без внесённых цен карточки снова показывают учебную сумму с меткой SYNTHETIC; наличие и цена продавца по-прежнему не подтверждены. При внесённой цене она отображается отдельно от учебной.

Причина расхождения со скриншотом: `frontend/lib/search.ts` создаёт демонстрационную строку перелёта по формуле `base * .43`; цена не получалась из Aviasales. Обе сравниваемые суммы обозначены RUB, признаков валютной ошибки в этой строке нет. Рабочая ссылка и импорт цены — разные операции: раньше цена не возвращалась из внешней страницы, а вручную внесённые суммы не обновляли основную демо-таблицу.

Во вкладке Aviasales наблюдалась реальная выдача MOW–AYT, 10–18 октября 2026, 5 пассажиров. Это подтверждает работу опубликованного формата ссылки; наличие выдачи для каждого нового маршрута не гарантируется. Для новых гостиничных URL проверены параметры, но получение живых результатов для каждого курорта ещё не подтверждено.

## Что ещё не работает

Автоматический импорт цен и предложений из внешних сайтов. Автоматический поиск конкретного пакетного тура. Точные ссылки Туту, авиакомпаний, Яндекс Путешествий, Travelata, Onlinetours и зарубежных туроператоров не подтверждены; переходы на их главные страницы убраны. Публичная поисковая ссылка Купибилета с датами и возрастом детей теперь проверена.

Для автоматического получения актуальных семейных тарифов Aviasales нужен собственный разрешённый [Flight Search API](https://support.travelpayouts.com/hc/en-us/articles/30565016140434-Aviasales-Flight-Search-API-real-time-and-multi-city-search). Документация требует одобренный доступ и собственные token/marker, описывает порог 50 000 MAU. Этот API не подключён. [Data API возвращает кэш](https://support.travelpayouts.com/hc/en-us/articles/204529267-FAQ-about-Aviasales-API) и не заменяет текущий поиск на конкретных пассажиров. Чужие ключи, внутренние endpoints и обход защиты не используются.

Level.Travel не загрузился при браузерной проверке. Его [официальные быстрые ссылки](https://help-partners.level.travel/fast-links) могут выбирать другую дату и длительность, поэтому они не используются как точный запрос. [Партнёрский API](https://help-partners.level.travel/api-copy) требует персональный ключ. [Документация модуля Слетать.ру](https://static.sletat.ru/Files/Manual/MODULES_Search_light.pdf) описывает параметры зарегистрированного модуля; наличие этих параметров не доказывает работу того же URL на главном сайте.

Формат авиассылки: [официальная документация Aviasales / Travelpayouts](https://support.travelpayouts.com/hc/ru/articles/5711895629714). Ссылка передаёт возрастные категории, но не конкретные возраста детей 2–11 лет. Год не передаётся; несовместимые с ближайшим годовым циклом даты блокируются.

Поставщики туров не подключены к этой форме. Для российского поиска нужны собственный официальный Tourvisor trial-token и справочники либо разрешённый API/модуль другого поставщика. Зарубежные операторы TUI / airtours, DERTOUR, Emirates Holidays и Turkish Airlines Holidays обозначены как кандидаты на проверку, а не активные интеграции.

## Открытые цены — обновление 28.09.2026

- Режим открытых цен показан при первом открытии сайта. Он загружает каталог наблюдений с локального API; встроенная копия показывает те же цены при недоступном backend. Цены сопровождаются датой наблюдения, источником и отметкой соответствия параметрам. Выбранное публичное предложение открывает разбивку расходов: найденные суммы со ссылками, остальные строки — «Не найдена».
- Проверена открытая выдача Aviasales SVO–HKT на 29.09–07.10.2026: 259 812 RUB за 5 пассажиров на момент наблюдения. В деталях самого дешёвого варианта — отсутствие зарегистрированного багажа и повторная регистрация при пересадках; эта ссылка не передаёт точные возраста детей.
- Через публичный интерфейс Купибилета проверена поисковая ссылка SVO–HKT на те же даты для 2 взрослых и детей 5/7/9 лет. Результат 260 904 RUB в выдаче; после перехода на страницу выбранного тарифа — 260 896 RUB. Ссылка из интерфейса указывает на конкретный тариф, но может истечь. В маршруте есть смена аэропорта BKK→DMK, поэтому он не удовлетворяет исходному фильтру без смены аэропорта. Требуемый багаж 20 кг для всех не подтверждён.
- Добавлен конструктор публичной ссылки Купибилета для перелётов и positioning. Формат проверен на сайте продавца. Ручное наблюдение теперь принимает как совпадающий URL Aviasales, так и Купибилет, включая число и возраста детей. Наблюдения старше 12 часов исключаются из текущей суммы расчёта.
- Открытые цены в каталоге не превращаются в полную стоимость поездки. Никаких автоматических вызовов закрытых интерфейсов, импорта цен из SPA без разрешённого API или бронирований нет.
